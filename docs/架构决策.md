## 2. 数据接口决策

### 2.1 网易云音乐API选择
- **决策**：使用 [NeteaseCloudMusicApi](https://github.com/Binaryify/NeteaseCloudMusicApi) 社区方案
- **理由**：
  1. 网易云音乐无官方开放API
  2. 该项目是社区最成熟的开源方案
  3. README已明确引用此API来源
- **风险**：
  - ⚠️ **鉴权风险**：需要处理登录态、Cookie管理
  - ⚠️ **限流风险**：频繁请求可能被限流
  - ⚠️ **合规风险**：需确保符合网易云使用条款
  - ⚠️ **版权风险**：音源URL可能有时效性
- **缓解措施**：
  - 实现请求频率限制
  - 本地缓存减少请求
  - 音源URL定期刷新
  - 提供接口替换机制（数据层抽象）
- **状态**：✅ 已选定

### 2.2 数据层架构
- **决策**：采用"可替换数据层"设计
- **架构**：
  ```
  UI层 → ViewModel → Repository → DataSource(接口抽象)
                                      ├─ NetEaseDataSource(网易云实现)
                                      └─ MockDataSource(测试/备用)
  ```
- **理由**：
  1. 便于接口替换或降级
  2. 方便测试和Mock
  3. 避免硬编码音源
- **状态**：⏳ 待实现

## 3. 核心功能架构决策

### 3.1 播放器架构
- **决策**：使用 HarmonyOS AVPlayer（音频播放）
- **架构**：
  - 播放服务（后台服务）
  - 播放状态管理（全局状态）
  - 播放队列管理
  - 歌词解析器
- **关键问题**：
  - 如何实现后台播放？→ 使用后台任务（Background Task）
  - 如何实现锁屏控制？→ 使用媒体会话（AVSession）
  - 如何处理音频焦点？→ 使用AVPlayer的音频焦点管理
- **状态**：⏳ 待实现

### 3.2 登录态管理
- **决策**：使用本地存储管理登录态
- **方案**：
  - Cookie持久化存储
  - 登录状态全局管理
  - Token刷新机制
- **状态**：⏳ 待实现

### 3.3 数据缓存策略
- **决策**：分级缓存
- **方案**：
  - 内存缓存：播放队列、当前歌曲信息
  - 本地缓存：用户信息、歌单列表、搜索历史
  - 音频缓存：播放缓存（不持久化下载）
- **状态**：⏳ 待实现
